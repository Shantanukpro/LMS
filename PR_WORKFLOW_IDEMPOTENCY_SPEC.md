# PR Workflow Comment Idempotency Specification

## Objective
The PR workflow comment task must not post duplicate comments or mark an issue `done` without producing or verifying a new artifact.

## Fingerprinting
Every comment generated by the workflow carries a unique HTML marker in its body:

```html
<!-- paperclip-pr-comment:fingerprint={unique-key} -->
```

The `unique-key` is derived from:
- The PR number (`context.issue.number`)
- A stable SHA-256 hash of the comment payload (repo + message)

Resulting format: `LMS-PR-WORKFLOW-{prNumber}-{commentHash}`

This makes the fingerprint deterministic per PR and content, while staying unique across PRs.

## Idempotency Algorithm
1. Compute the fingerprint from the PR number and intended comment payload.
2. Query the PR for existing comments via the GitHub API.
3. Search for a comment containing the expected fingerprint marker.
4. If found, report the existing evidence (`html_url`, `id`, `created_at`) and exit without creating a new comment.
5. If not found, create the comment and record the new evidence.
6. Only transition the associated issue to `done` when a new comment is created or a missing recorded artifact is verified.

## Workflow Implementation
The reusable workflow is implemented in `.github/workflows/pr-comment.yml` and uses `actions/github-script` to perform the check.

### Outputs
- `comment-url`: URL of the existing or newly created comment.
- `fingerprint`: The computed fingerprint for this run.
- `created`: `true` if a new comment was created, `false` if one already existed.
- `evidence`: JSON blob containing the evidence type and metadata.

## Acceptance Criteria Mapping
- **Query prior state:** The workflow lists all existing PR comments before posting.
- **Detect existing work:** The fingerprint marker lets the workflow detect an already-posted comment.
- **Report evidence:** Existing comments are logged with their URL, ID, and timestamp.
- **No redundant done:** The workflow exits without creating a new artifact when the comment already exists.
- **Deterministic fingerprint:** Each run computes the same fingerprint for the same PR + content combination.

## Verification Steps
1. Open a test PR against the repository.
2. Confirm the workflow runs and creates a comment with the fingerprint marker.
3. Re-run the workflow on the same PR.
4. Confirm the workflow logs the existing comment URL and does not create a duplicate.
5. Inspect the step output `created` is `false` on the re-run and `true` on the first run.
